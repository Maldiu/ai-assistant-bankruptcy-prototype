# AI-ассистент юриста по банкротству физических лиц

Прототип AI-агента для первичной квалификации клиентов и ответов на базовые вопросы
по банкротству физических лиц. Собран на **Dify** (workflow + база знаний), модель —
GPT-5.6 Sol через OpenAI-совместимый провайдер. Агент ведёт клиента по сценарию,
собирает факты (долг, просрочка, доход, имущество, исполнительное производство,
регион), отвечает на базовые вопросы по процедуре и формирует обращение юристу.

**Быстрый старт:** см. `DEPLOY.md` (развернуть за ~20 минут).

## Что умеет

- Квалифицирует клиента по долгам: сумма, состав задолженности, просрочка, доход,
  имущество, исполнительное производство, регион, предыдущее банкротство.
- Отвечает на базовые вопросы: внесудебное vs судебное банкротство, сроки, стоимость,
  единственное жильё, ипотека, кредит после банкротства, коллекторы и цессия.
- Не выдумывает: если факта нет в базе знаний — честно говорит «не знаю» и
  предлагает консультацию юриста.
- Не даёт юридически опасных советов: отказывается помогать скрывать имущество
  и объясняет последствия (оспаривание сделок за 3 года, ст. 195–197 УК РФ).
- Доводит до заявки: после сбора фактов формирует карточку обращения и передаёт
  юристу. Служебный блок в чат клиенту не попадает.
- Защита от промпт-инъекций: отказывается играть по правилам клиента, раскрывать
  системный промпт и внутреннюю структуру базы.

## Архитектура (Dify workflow)

```
start → kb (retrieval, top_k=10) → llm (GPT-5.6 Sol) → code (сборка тикета)
      → if-else (code.has == 1) → http (push в датасет «Обращения клиентов»)
                                → answer ({{#code1.reply#}})
```

- База знаний: один Markdown-файл, 13 разделов (~50 KB, 62 заголовка H2),
  кастомный чанкинг (разделитель `## `, max_tokens 800, overlap 80).
- Системный промпт: 19 правил, ~6.9 KB. Правила 16–19 добавлены по итогам
  тестирования (короткое «нет» как факт, ответ только на русском, не переспрашивать
  известные факты, не копировать шаблон в тикет).
- Retrieval: `top_k` поднят с 6 до 10 после тестов на разговорных формулировках.

## Результаты тестирования

- 10 сценариев / 40+ ходов: штатные пути, граничные случаи, провокации,
  промпт-инъекции (RU/EN), попытки вытащить системный промпт.
- 7 слабостей найдено и исправлено (см. `docs/primery-dialogov.pdf`, раздел 2):
  отказ отвечать там, где ответ в базе; разговорная формулировка не находила ответ;
  инъекция стиля; юридическая ловушка «перепишу квартиру на маму»; короткое «нет»;
  шаблонный текст в тикете; пробел в базе по коллекторам и цессии.
- Метрика релевантности запроса «сколько стоит» после правки: 0.90.

## Нюансы для внедрения

Защита от промпт-инъекций держится на промпте. Для продакшена нужен второй слой:
guardrails и фильтрация входа/выхода. Это записано в плане внедрения, а не
выдаётся за решённую задачу.

## Структура репозитория

```
knowledge-base/   # KB: 13 разделов + объединённый файл + статьи УК РФ
prompts/          # системный промпт (экспорт из Dify)
workflow/         # описание графа + код-нода + DSL (экспорт из Dify)
docs/             # PDF/HTML с примерами диалогов и отчёт по заданию
# (сырые стенограммы убраны; примеры диалогов - в docs/primery-dialogov.pdf)
tests/            # PowerShell-раннеры диалогов через Service API
```

## Как воспроизвести

1. Создать приложение-воркфлоу в Dify, импортировать DSL из `workflow/`.
2. Загрузить `knowledge-base/bazaznanii-bankrotstvo-fizlic.md` как датасет,
   настройки чанкинга: разделитель `## `, max_tokens 800, overlap 80.
3. Создать второй датасет «Обращения клиентов» для приёма тикетов.
4. Подключить модель через OpenAI-совместимый провайдер.
5. Опубликовать и протестировать по сценариям из `dialogues/`.
